# 운영자 안내 (한 쪽)

5ft.mag 를 혼자 운영하는 사람을 위한 안내다. 개발 지식 없이 따라 할 수 있게 썼다. 기술 세부는 `CLAUDE.md`, 장애·복구는 `docs/maintenance.md`·`docs/database-recovery.md`·`docs/secrets-rotation.md` 를 본다.

## 저장소에서 하는 일 (Claude 에게 요청)

아래는 관리 화면이 아니라 저장소 작업이다. Claude Code 세션에서 요청하면 PR 을 만들고 검사를 통과시켜 배포까지 한다.

- **새 기사 발행** (한국어 + 영문 + 일문): 원고·사진을 주고 "기사로 작성해줘". `new-article` 절차대로 세 언어판을 한 PR 로 받는다.
- **기사 본문 수정**: 기사 URL과 고칠 내용을 알려 준다. 한국어·영문·일문 본문, 메타데이터와 목록 정보를 함께 확인하고 같은 PR에서 검수한다.
- **기사 번역**: 한국어 원문과 변경 범위를 전달한다. 영문·일문 파일, 날짜·분류·캡션·링크와 목록 표시 상태를 원문과 함께 확인한다.
- **예약 발행**: 기사 자동 예약 기능은 지원하지 않는다. 공개할 시점에 검수된 PR을 머지·배포한다. 미래 날짜만 입력해도 발행이 예약되지 않는다. 배포 파일에 올린 원고는 목록에서 숨겨도 URL로 읽을 수 있으므로 공개 전 원고는 배포 대상과 분리한다.
- **현상소·수리실의 "최종 반영" 날짜**, **홈 테마 필름**, **About 문구**, **메뉴·푸터** 같은 정적 문구.
- **필름·현상소 대량 등록**(열 개 이상): 표로 주면 SQL 로 한 번에 넣는다.

### 지원되는 기사 발행 경로
새 기사·본문 수정·번역은 저장소 작업 → 공통 셸·이미지·번역·RSS·사이트맵 검수 → PR의 CI 통과 → 승인된 내용 머지·배포 순서로 진행한다. 배포 후 세 언어판과 목록을 확인한다.

구형 「기사 작성」·「편집」 진입점은 제거했다. 옛 `admin/article-editor.html` 주소를 열어도 안내만 보이며 초안 HTML을 불러오거나 저장·미리보기·발행하지 않는다. GitHub 토큰 입력·저장 기능도 제거했고 이 주소를 열면 이전에 보관한 토큰을 현재 브라우저의 로컬·세션 저장소에서 삭제한다. 기존 DB 초안은 삭제하지 않았으므로 필요하면 담당자에게 복구를 요청한다.

목록 상태 조회가 실패하면 “확인 불가”와 재조회 버튼이 보이고 변경 스위치를 사용할 수 없다. 이전 조회가 성공했다면 마지막 성공 시각과 이전 상태를 표시한다. 이 상태를 현재 상태로 판단하지 말고 재조회가 성공한 뒤 변경한다. “목록에서 숨김”은 비공개 원고·엠바고·유료 자료의 접근 보호 수단이 아니다.

## 편집부 홈의 조회 상태

- **0건**: 해당 항목의 조회가 성공했고 처리할 항목이 없다.
- **확인 불가**: 통신 실패·권한 문제·응답 누락 등으로 확인하지 못했다. 처리할 일이 없다는 뜻이 아니다. 해당 항목의 “다시 시도”를 누른다. 다른 항목의 성공 결과는 유지된다.
- **이전 값**: 이 탭에서 마지막으로 성공한 값과 시각을 유지한 것이다. 최신 조회에 실패했으므로 현재 값으로 판단하지 않는다. 새로고침하거나 탭을 닫으면 이 임시 값은 남지 않는다.

## 배포는 어떻게 되나

- `main` 에 머지되면 1~2분 안에 Netlify 가 사이트를 다시 만든다.
- 데이터베이스 변경이 든 PR 은 머지 뒤 GitHub Actions 의 "Supabase Migrations" 가 성공(초록)인지 본다. 실패하면 `docs/secrets-rotation.md` 의 토큰 갱신 절차를 따른다.
- 서버 함수(`supabase/functions/`)가 든 PR 은 "Supabase Edge Functions" 도 본다.
- 새 기사가 들어오면 RSS·사이트맵은 자동 갱신 워크플로우(feeds-sync)가 따라간다. 관리 화면에서 기사를 “목록에서 숨김”으로 바꾸면 다음 빌드(매일 새벽 또는 다음 배포) 때 RSS·사이트맵도 따라간다. 기사 파일의 직접 URL 접근은 그대로다.
