# 운영자 안내 (한 쪽)

5ft.mag 를 혼자 운영하는 사람을 위한 안내다. 개발 지식 없이 따라 할 수 있게 썼다. 기술 세부는 `CLAUDE.md`, 장애·복구는 `docs/maintenance.md`·`docs/database-recovery.md`·`docs/secrets-rotation.md` 를 본다.

## 어디서 무엇을 하나

| 하고 싶은 일 | 어디서 | 메모 |
|---|---|---|
| 독자 사진 승인·반려, 이주의 사진 선정 | 관리 → Reader's Roll 검토 (`admin/submissions.html`), 이주의 사진 (`admin/potw.html`) | 반려할 때는 사유를 적어 준다. 사유가 없으면 독자에게 가는 알림이 빈 곳을 가리킨다. |
| 필름 추가·수정, 캔 그림 | 관리 → 필름 카탈로그 (`admin/films.html`) | 영문·일문 소개 칸을 비우면 영어 → 한국어 순으로 대신 나간다. 새 필름의 상세 페이지와 사이트맵은 다음 빌드(매일 새벽 또는 다음 배포) 때 생긴다. |
| 현상소·수리실 정보, 가격 | 관리 → 현상소 (`admin/labs.html`), 수리실 (`admin/repairs.html`) | 공개 페이지의 "최종 반영" 날짜는 저장소 작업으로 바뀐다(정비 D2 에서 자동화 예정). |

## 저장소에서 하는 일 (Claude 에게 요청)

아래는 관리 화면이 아니라 저장소 작업이다. Claude Code 세션에서 요청하면 PR 을 만들고 검사를 통과시켜 배포까지 한다.

- **새 기사 발행** (한국어 + 영문 + 일문): 원고·사진을 주고 "기사로 작성해줘". `new-article` 절차대로 세 언어판을 한 PR 로 받는다.
- **기사 본문 수정**: 고칠 내용을 알려 준다. 관리 화면의 「기사 작성」·「편집」은 지금 쓰지 않는다(아래 주의).
- **현상소·수리실의 "최종 반영" 날짜**, **홈 테마 필름**, **About 문구**, **메뉴·푸터** 같은 정적 문구.
- **필름·현상소 대량 등록**(열 개 이상): 표로 주면 SQL 로 한 번에 넣는다.

### 주의: 관리 화면의 「기사 작성」·「편집」
「기사 작성」 화면이 만드는 기사 틀은 6월에 굳은 옛 틀이라, 거기서 만든 PR 은 검사를 통과하지 못한다. 기사 목록의 「편집」은 해당 기사가 아니라 빈 편집기를 열고, 그대로 「PR 만들기」를 누르면 실제 기사를 덮어쓸 수 있다. 방향을 새로 정할 때까지 두 버튼은 쓰지 않는다.

## 배포는 어떻게 되나

- `main` 에 머지되면 1~2분 안에 Netlify 가 사이트를 다시 만든다.
- 데이터베이스 변경이 든 PR 은 머지 뒤 GitHub Actions 의 "Supabase Migrations" 가 성공(초록)인지 본다. 실패하면 `docs/secrets-rotation.md` 의 토큰 갱신 절차를 따른다.
- 서버 함수(`supabase/functions/`)가 든 PR 은 "Supabase Edge Functions" 도 본다.
- 새 기사가 들어오면 RSS·사이트맵은 자동 갱신 워크플로우(feeds-sync)가 따라간다. 관리 화면에서 기사를 비공개로 바꾸면 다음 빌드(매일 새벽 또는 다음 배포) 때 RSS·사이트맵도 따라간다.
